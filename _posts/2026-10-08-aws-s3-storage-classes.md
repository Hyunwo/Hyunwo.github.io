[지난 글](/2026/10/07/aws-s3-basics/)에서 S3의 버킷·객체 구조와 내구성, 비용을 정리했다. 이번 글에서는 S3가 목적과 예산에 맞춰 제공하는 **스토리지 클래스**를 살펴본다. 모든 데이터를 하나의 방식으로 저장하는 대신, 접근 빈도와 중요도에 맞는 클래스를 고르게 해서 비용을 줄이는 구조다.

## 스토리지 클래스: 9가지를 Standard와 비교해서 보기

S3는 크게 **파일 저장용**과 **아카이브용**으로 나뉘는 클래스를 제공한다. 외울 때는 기준점인 **S3 Standard**를 먼저 잡고, 나머지가 Standard와 무엇이 다른지(보관 위치, 최소 보관 기간, 조회 속도, 조회 요금)를 비교하는 방식이 효율적이다. 아무 설정을 하지 않고 올리면 Standard로 저장된다.

![S3 스토리지 클래스 비교](/assets/images/aws-s3-storage-classes/s3_storage_classes.png)

참고로 강의에서 9번째로 소개한 S3 on Outposts도 AWS는 스토리지 클래스로 분류한다. 다만 성격은 온프레미스(Outposts 장비)에서 S3 API를 쓰는 방식에 가까워서 이 글에서는 자세히 다루지 않는다.

## S3 Standard: 모든 비교의 기준

Standard는 3개 이상의 AZ에 데이터를 저장하고, 설계 가용성 99.99%, 내구성 11 나인을 제공한다. 최소 보관 기간도, 최소 객체 크기 제약도, 조회 요금도 없다. 자주 접근하는 일반적인 데이터라면 Standard를 쓰면 된다.

## 자주 쓰지 않는 데이터: Standard-IA와 One Zone-IA

**Standard-IA(Infrequent Access)** 는 자주 쓰지 않지만 잃어버리면 안 되는 데이터용이다. Standard처럼 3개 이상의 AZ에 저장해서 내구성이 높고, 저장 비용은 Standard보다 낮다. 대신 세 가지 조건이 붙는다.

- **최소 보관 기간 30일**: 10일만 두고 지워도 30일치가 과금된다. 30일 동안 반드시 보관해야 한다는 뜻이 아니라 요금 계산상 그렇게 취급한다는 의미다.
- **최소 과금 크기 128KB**: 100KB 파일을 올려도 128KB로 계산한다. 파일을 늘려서 올릴 필요는 없다.
- **조회 요금**: 데이터를 읽을 때마다 GB당 조회 요금이 붙는다.

따라서 저장은 오래 하지만 꺼낼 일이 드문 데이터에 유리하다.

**One Zone-IA**는 같은 조건에서 **단 하나의 AZ에만** 저장해 가격을 더 낮춘 클래스다. 그 AZ에 장애가 나거나 AZ 자체가 손실되면 데이터를 잃을 수 있다. 그래서 오래된 썸네일처럼 원본만 있으면 다시 만들 수 있는 데이터, 또는 다른 곳에 원본이 있는 보조 백업에 어울린다. (강의 자막에는 이 클래스가 "Glacier IA"로 나오는데 One Zone-IA를 가리키는 것으로 보인다.)

## S3 Express One Zone: 가장 빠르지만 가장 비싼 클래스

Express One Zone은 지연 시간이 중요한 워크로드를 위한 클래스로, 요청 지연이 한 자릿수 밀리초 수준이다. Standard보다 최대 10배 빠르다고 소개되고, 요청 비용은 크게 낮지만 저장 비용은 Standard보다 몇 배 비싸다. 저장 위치는 일반 버킷이 아니라 **디렉터리 버킷**이며 단일 AZ에 둔다. 컴퓨팅 리소스를 같은 AZ에 두면 거리가 줄어 더 빨라진다. 머신러닝 학습이나 빅데이터 처리처럼 대량의 데이터를 빠르게 읽어야 할 때 쓴다.

> 강의 시점에는 서울 리전에서 쓸 수 없다고 했지만, 현재 AWS 문서의 지원 리전 목록에는 서울(`ap-northeast-2`)이 포함되어 있다(2026년 10월 확인). 요청 비용 절감 폭도 강의에서는 50%라고 했으나 이후 가격 인하로 최대 80% 수준까지 낮아졌다. 최신 가격은 공식 요금표에서 확인하는 것이 정확하다.

## 아카이브: Glacier 세 가지

Glacier 계열은 오래 보관하는 대신 최소 보관 기간이 길다. 핵심 차이는 **얼마나 빨리 꺼낼 수 있는가**다.

| 클래스 | 최소 보관 | 조회 시간 | 어울리는 용도 |
|---|---|---|---|
| **Glacier Instant Retrieval** | 90일 | 밀리초(즉시) | 의료 영상, 뉴스 미디어처럼 거의 안 보지만 필요할 땐 바로 봐야 하는 데이터 |
| **Glacier Flexible Retrieval** | 90일 | Expedited 1~5분, Standard 3~5시간, Bulk 5~12시간 | 백업, 재해 복구 데이터 |
| **Glacier Deep Archive** | 180일 | Standard 12시간 이내, Bulk 48시간 이내 | 법적 보관 의무가 있는 기록, 오래된 로그 |

Instant Retrieval은 아카이브 가격이지만 접근은 Standard처럼 즉시 된다. 128KB 최소 과금 크기가 있다. Flexible Retrieval과 Deep Archive는 객체마다 약 40KB의 메타데이터 오버헤드가 붙고, 꺼내려면 먼저 **복원(restore) 요청**을 보내 임시 복사본을 만든 뒤 접근해야 한다. 강의에서는 Deep Archive의 최소 보관 기간이 다른 클래스와 비슷하다고 넘어갔는데, 실제로는 **180일**로 가장 길다. 조회도 "3~4일"이 아니라 12~48시간 범위다. 대신 저장 비용은 가장 저렴하다.

## 자동으로 옮겨주는 Intelligent-Tiering

파일이 수천, 수억 개가 되면 하나하나 클래스를 정하기 어렵다. **Intelligent-Tiering**은 객체의 접근 패턴을 보고 자동으로 계층을 옮겨 주는 클래스다. 접근이 없으면 30일 뒤 Infrequent Access 계층, 90일 뒤 Archive Instant Access 계층으로 내려가고, 선택 사항인 Archive/Deep Archive Access 계층(90일/180일)도 켤 수 있다. 다시 접근하면 Frequent Access 계층으로 돌아온다.

강의에서는 계층을 옮길 때마다 비용이 발생한다고 했는데, 정확히는 **계층 이동 비용이 아니라 객체 수에 비례하는 월 모니터링·자동화 요금**이 붙는다. 조회 요금은 없고, 128KB 미만 객체는 자동 계층화 대상이 아니라 Frequent Access 요금으로 저장되며 모니터링 요금도 없다. 접근 패턴을 알 수 없을 때 선택할 만하다.

## 저장 비용 감각

강의에서 서울 리전 기준으로 언급한 GB당 월 저장 비용은 대략 아래 순서였다. 자막 인식이 불안정한 수치이므로 감각을 잡는 용도로만 보고, 실제 금액은 [공식 요금표](https://aws.amazon.com/s3/pricing/)에서 확인하자.

| 클래스 | 대략적인 저장 비용(GB/월) |
|---|---|
| Standard | $0.025 |
| Standard-IA | $0.0138 |
| One Zone-IA | $0.011 |
| Glacier Instant Retrieval | $0.005 |
| Glacier Flexible Retrieval | $0.0045 |
| Glacier Deep Archive | $0.002 |

Standard 대비 Standard-IA는 약 절반, Instant Retrieval은 약 1/5, Deep Archive는 1/10 이하다. 다만 저렴한 클래스일수록 조회 요금과 최소 보관 기간 조건이 붙으므로 저장 단가만 보고 고르면 안 된다.

## 클래스 바꾸기: 직접 변경, 수명 주기, Intelligent-Tiering

콘솔에서 객체를 선택하고 **스토리지 클래스 편집**을 누르면 클래스를 바꿀 수 있고, 클래스별 조건(최소 보관 기간, 최소 객체 크기)도 함께 안내된다. 하지만 객체가 수만 개가 되면 일일이 바꿀 수 없다. 현실적인 방법은 두 가지다.

- **수명 주기(Lifecycle) 규칙**: "30일 뒤 Standard-IA, 60일 뒤 Glacier로 이동"처럼 조건을 정해 자동으로 옮긴다. 다음 글들에서 따로 다룬다.
- **Intelligent-Tiering**: 접근 패턴을 모르겠다면 S3가 알아서 옮기게 맡긴다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| **스토리지 클래스** | 접근 빈도와 중요도에 맞춰 선택하는 S3 저장 방식. 비용·가용성·조회 방식이 다르다 |
| **S3 Standard** | 기본 클래스. 3개 이상 AZ, 최소 보관 기간·조회 요금 없음 |
| **Standard-IA** | 드물게 접근하는 중요 데이터용. 최소 30일, 128KB 과금, 조회 요금 |
| **One Zone-IA** | IA와 같지만 단일 AZ에만 저장. 다시 만들 수 있는 데이터용 |
| **Express One Zone** | 단일 AZ·디렉터리 버킷 기반의 초저지연 클래스 |
| **Glacier Instant Retrieval** | 아카이브 가격에 즉시 조회. 최소 90일 |
| **Glacier Flexible Retrieval** | 분~시간 단위 복원이 필요한 아카이브. 최소 90일 |
| **Glacier Deep Archive** | 가장 저렴한 장기 보관. 최소 180일, 12~48시간 복원 |
| **Intelligent-Tiering** | 접근 패턴에 따라 자동으로 계층을 옮기는 클래스. 월 모니터링 요금 발생 |
| **최소 보관 기간** | 그 전에 삭제하거나 옮겨도 해당 기간만큼 과금하는 조건 |
| **복원(Restore)** | Glacier Flexible/Deep Archive 객체를 읽기 위해 임시 복사본을 만드는 작업 |

다음 글에서는 오늘 예고한 수명 주기 규칙처럼, 객체의 클래스를 시간에 따라 자동으로 관리하는 S3 기능을 이어서 다룬다.
