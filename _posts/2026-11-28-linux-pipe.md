앞의 두 글에서 `grep`으로 오류 줄을 골라 파일에 저장하는 데까지 왔다. 그런데 "어떤 오류가 몇 번 났는가"를 알고 싶다면 중간 결과를 파일에 저장하고 다시 읽는 일을 반복해야 한다. 파이프(`|`)는 앞 명령의 출력을 다음 명령의 입력으로 곧바로 넘겨서, 작은 명령 여러 개를 하나의 처리 과정으로 만든다. 이 글은 `cut`, `sort`, `uniq`, `wc`를 파이프로 연결해 로그의 오류 종류별 건수를 집계하고, 마지막에 결과를 파일로 저장하는 흐름을 다룬다. 실습은 앞 글의 `~/linux-lab/search-lab`과 같은 예제 로그(`logs/app.log`, 12줄)를 사용한다.

## 파이프는 무엇을 연결하는가

파이프는 앞 명령의 **표준 출력**을 다음 명령의 **표준 입력**으로 넘기는 연결이다.

```text
명령 A  --표준 출력-->  |  --표준 입력-->  명령 B
```

앞에서 결과를 내보내고, 뒤에서 받아 처리하는 통로를 이어 두었다고 생각하면 된다. 이 때문에 파이프 뒤쪽 명령에는 읽을 파일 이름을 다시 적지 않는다. 앞에서 넘어온 내용이 이미 입력이기 때문이다.

리다이렉션과 비교하면 연결하는 대상이 다르다.

| 구분 | 기호 | 연결하는 대상 | 예시 |
|---|---|---|---|
| 출력 리다이렉션 | `>`, `>>` | 명령의 출력 → **파일** | `grep ... > errors.log` |
| 입력 리다이렉션 | `<` | **파일** → 명령의 입력 | `wc -l < day1.txt` |
| 파이프 | `\|` | 명령의 출력 → **다른 명령**의 입력 | `grep ... \| wc -l` |

기본 파이프는 표준 출력만 넘긴다. 오류 메시지(표준 오류)는 파이프를 거치지 않고 화면으로 나온다.

## 로그에서 오류를 세는 흐름은 어떻게 만드는가

앞 글의 예제 로그에서 ERROR 줄은 5개이고, 오류 종류는 `TIMEOUT`, `DISK_FULL`, `CONNECT_FAILED` 세 가지다. 이 정보를 명령 몇 개로 뽑아 본다. 모든 단계는 왼쪽부터 하나씩 실행해서 중간 결과를 확인하며 진행한다.

### 1단계: 오류 줄의 개수를 센다

```bash
grep -F ' ERROR ' logs/app.log | wc -l
# 5
```

`grep -F`가 `ERROR`가 들어 있는 줄을 골라 표준 출력으로 내보내고, `|`로 넘어온 내용을 `wc -l`이 받아 줄바꿈의 수를 센다. 파일 이름을 적지 않았으므로 결과는 숫자만 나온다. `-l`은 정확히는 줄바꿈 문자를 세는 옵션이고, 예제 로그의 각 기록은 줄바꿈으로 끝나므로 기록 수도 5건으로 읽힌다.

### 2단계: 필요한 칸만 꺼낸다

로그 한 줄은 공백으로 나뉘는 칸(필드)으로 이루어져 있다.

```text
2026-11-27 09:01:12 ERROR TIMEOUT db connection timed out
   1          2       3      4         5 ...
```

`cut`은 한 줄을 정해진 구분자로 나눠서 원하는 칸만 꺼내는 명령이다.

```bash
cut -d ' ' -f 4 reports/errors.log
```

| 옵션 | 의미 |
|---|---|
| `-d ' '` | 칸을 나눌 구분자를 정한다. 작은따옴표 사이에 **실제 공백 한 칸**을 넣는다 |
| `-f 4` | 나뉜 칸 중 **네 번째**를 꺼낸다 |

`cut`은 `-d`로 구분자를, `-f`로 칸 번호를 정한 뒤 읽을 파일을 적는다. 칸이 일정한 모양으로 나뉘는 자료에 쓴다. 결과는 다음과 같다.

```text
TIMEOUT
DISK_FULL
TIMEOUT
CONNECT_FAILED
TIMEOUT
```

이번에는 파일을 직접 읽는 대신 앞 명령의 결과를 이어 받도록 파이프로 연결한다.

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4
```

앞의 `grep`은 12줄에서 오류 줄만 고르고, 뒤의 `cut`은 넘어온 각 줄에서 4번째 칸만 남긴다. 파이프로 넘어오는 내용을 받으므로 `cut` 뒤에 `errors.log`를 적지 않는다.

### 3단계: 같은 종류끼리 모아 중복을 합친다

`uniq`는 **바로 이웃한 같은 줄**을 하나로 합치는 명령이다.

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4 | uniq
```

결과가 위의 5줄 그대로다. `TIMEOUT`이 세 번 나왔지만 떨어져 있어서 이웃한 같은 줄이 하나도 없기 때문이다. 떨어져 있는 같은 항목까지 합치려면 먼저 정렬해서 같은 항목이 붙어 있게 해야 한다.

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4 | sort | uniq
```

```text
CONNECT_FAILED
DISK_FULL
TIMEOUT
```

발생한 오류 종류가 세 가지라는 것을 알 수 있다.

### 4단계: 종류별 건수를 센다

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4 | sort | uniq -c
```

```text
      1 CONNECT_FAILED
      1 DISK_FULL
      3 TIMEOUT
```

`uniq`의 `-c` 옵션은 하나로 합친 줄이 몇 번 연속해서 있었는지 세고, 그 수를 줄 앞에 표시한다. 이 집계가 정확한 이유는 앞의 `sort`가 같은 코드끼리 먼저 모아 두었기 때문이다.

### 5단계: 많이 발생한 순서로 정렬한다

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4 | sort | uniq -c | sort -nr
```

```text
      3 TIMEOUT
      1 DISK_FULL
      1 CONNECT_FAILED
```

| 옵션 | 의미 |
|---|---|
| `-n` | 글자 순서 대신 **숫자의 크기**로 비교한다 (줄 맨 앞의 값을 숫자로 읽는다) |
| `-r` | 비교 순서를 뒤집어 **큰 수부터** 나오게 한다 |

앞의 `sort`는 같은 코드끼리 모으는 역할이고, 마지막 `sort -nr`은 집계된 건수를 큰 순서로 보여 주는 역할이다. 건수가 같은 항목끼리의 순서는 `-r` 때문에 뒤집혀 나올 수 있으니 순서가 달라도 놀라지 않는다. 이렇게 많이 발생한 문제부터 정리하면 어떤 오류를 먼저 살펴볼지 판단하기 쉽다.

### 6단계: 결과를 파일로 저장한다

```bash
grep -F ' ERROR ' logs/app.log | cut -d ' ' -f 4 | sort | uniq -c | sort -nr > reports/error-counts.txt
cat reports/error-counts.txt
```

완성된 집계 결과를 `reports` 폴더에 저장해 두면 다음에도 읽을 수 있다. 파이프의 마지막 출력에 `>`를 붙이는 것이므로 중간 단계는 화면에도 파일에도 남지 않는다.

<!-- 이미지 추가 위치: 로그에서 오류 집계까지 명령 흐름 정리 이미지 -->

전체 흐름은 다음과 같이 데이터가 줄어들고 요약되는 과정이다.

```text
app.log (12줄)
   │ grep -F ' ERROR '      ERROR가 있는 줄만 고른다
   ▼
오류 기록 (5줄)
   │ cut -d ' ' -f 4        4번째 칸(오류 종류)만 남긴다
   ▼
TIMEOUT, DISK_FULL, TIMEOUT, CONNECT_FAILED, TIMEOUT (5줄)
   │ sort                   같은 종류끼리 붙인다
   ▼
CONNECT_FAILED, DISK_FULL, TIMEOUT, TIMEOUT, TIMEOUT (5줄)
   │ uniq -c                붙은 줄을 합치고 건수를 센다
   ▼
1 CONNECT_FAILED / 1 DISK_FULL / 3 TIMEOUT (3줄)
   │ sort -nr               건수가 큰 순서로 정렬한다
   ▼
3 TIMEOUT / 1 DISK_FULL / 1 CONNECT_FAILED → reports/error-counts.txt
```

처음에는 긴 기록이 보이지만, 중간에는 짧은 항목 목록이, 끝에는 종류와 건수가 보인다.

## 파이프를 쓸 때 주의할 점은 무엇인가

### 한 단계를 붙일 때마다 중간 결과를 확인한다

명령을 길게 이어 붙이면 어디서 예상과 달라졌는지 찾기 어렵다. 한 단계 붙일 때마다 실행해 결과를 보면, 문제가 생긴 단계를 바로 알 수 있다. 명령을 연결할 때는 마지막 숫자만 보지 말고, 각 단계에 어떤 내용이 몇 줄 들어오는지도 함께 확인한다. 예를 들어 `grep` 다음에 `wc -l`을 붙여 5줄이 나오는지, `cut` 이후에도 5줄인지 확인한다.

### 같은 항목을 세기 전에는 반드시 정렬한다

`uniq`는 이웃한 줄만 비교한다. 정렬 없이 `uniq -c`를 쓰면 같은 항목이 떨어져 있을 때 따로 세어져 집계가 틀린다.

### 건수 정렬에는 `-n`을 붙인다

숫자를 글자로 비교하면 `10`이 `2`보다 앞에 놓인다. 첫 글자 `1`이 `2`보다 작기 때문이다. 건수처럼 숫자의 크기로 정렬할 때는 `-n`이 필요하다.

### 파이프는 표준 출력만 넘긴다

앞 명령이 내보내는 오류 메시지는 파이프로 넘어가지 않고 화면에 나온다. 오류까지 함께 넘기려면 `2>&1`로 오류를 표준 출력에 합친다. 컨테이너 로그를 `grep`으로 필터링할 때 자주 마주치는 상황이다.

```bash
docker logs myapp 2>&1 | grep -F ' ERROR '
```

`docker logs`는 컨테이너의 표준 출력과 표준 오류를 각각 해당 통로로 내보내기 때문에, `2>&1` 없이 파이프만 쓰면 표준 오류 쪽 로그가 필터를 거치지 않고 화면에 그대로 나온다.

### `cut`은 공백이 여러 칸이면 칸이 어긋난다

`cut -d ' '`는 공백 하나마다 칸을 나눈다. 로그 정렬을 위해 공백이 두 칸 이상 들어 있으면 빈 칸이 생겨 4번째 칸이 의도와 달라진다. 이런 자료에서는 연속된 공백을 하나로 처리하는 `awk '{print $4}'`를 쓴다. `cut`은 칸이 정확한 모양으로 나뉘는 자료에 적합하다.

### 파이프라인의 성공 여부는 마지막 명령만 알려 준다

`echo $?`로 확인하는 종료 상태는 기본적으로 파이프의 **마지막 명령**의 결과다. 중간 단계가 실패해도 마지막 명령이 성공하면 0이 나올 수 있다. bash에서 `echo "${PIPESTATUS[@]}"`를 실행하면 각 단계의 종료 상태를 모두 볼 수 있다.

## 현업에서는 파이프를 어디에 쓰는가

파이프의 가치는 "작은 도구를 필요한 만큼 조립하는 것"이다. 한 번만 쓰고 버릴 분석에 별도 프로그램을 만들지 않아도 된다. 서버 상태를 확인할 때 자주 쓰는 조합은 다음과 같다.

| 상황 | 명령 | 하는 일 |
|---|---|---|
| 디렉터리별 용량 상위 확인 | `du -sh ~/* \| sort -rh \| head -n 5` | 크기를 읽기 쉬운 단위로 정렬해 상위 5개 출력 |
| 현재 폴더의 항목 개수 | `ls \| wc -l` | 목록을 줄 수로 센다 |
| 쿠버네티스 로그 오류 건수 | `kubectl logs deploy/myapp \| grep -F ' ERROR ' \| wc -l` | 로그에서 오류 줄 수 세기 |
| 로그를 실시간으로 보며 필터링 | `tail -f logs/app.log \| grep -F ' ERROR '` | 새로 쌓이는 기록 중 오류만 계속 출력 |
| 특정 프로세스 확인 | `ps aux \| grep -F nginx` | 프로세스 목록에서 이름으로 찾기 (`grep` 자신도 목록에 나올 수 있음) |
| 이미 집계한 결과 확인 | `sort reports/error-counts.txt \| head -n 3` | 상위 3개만 보기 |

`head`와 `tail`도 파이프에 자주 쓰인다. 위 표의 `sort -rh`에서 `-h`는 `K`, `M`, `G` 같은 단위가 붙은 크기를 크기 순으로 비교하는 옵션이다. 로그의 칸 번호나 구분자만 바꾸면 요청 경로별 건수, 클라이언트 IP별 건수처럼 같은 형태의 집계를 응용할 수 있다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| 파이프 (`\|`) | 앞 명령의 표준 출력을 다음 명령의 표준 입력으로 넘기는 연결 |
| 파이프라인 | 파이프로 여러 명령을 이어 붙인 하나의 처리 흐름 |
| 필드 (칸) | 한 줄을 구분자로 나눴을 때 각각의 조각 |
| 구분자 | 칸과 칸을 나누는 기준이 되는 글자 (예: 공백) |
| `cut` | 한 줄에서 구분자로 나눈 칸 중 원하는 칸만 꺼내는 명령 |
| `-d` / `-f` | `cut`에서 구분자를 정하는 옵션 / 꺼낼 칸 번호를 정하는 옵션 |
| `sort` | 줄을 순서대로 정렬하는 명령. 기본은 글자 기준 |
| `-n` / `-r` | 숫자 크기로 비교 / 정렬 순서 뒤집기 |
| `uniq` | 바로 이웃한 같은 줄을 하나로 합치는 명령 |
| `uniq -c` | 합친 줄이 몇 번 반복되었는지 앞에 횟수를 붙이는 옵션 |
| `wc -l` | 줄바꿈 문자의 수, 즉 줄 수를 세는 명령 |
| 집계 | 같은 항목을 묶어 건수를 세는 일 |
| `2>&1` | 표준 오류를 표준 출력으로 합쳐 파이프로 함께 넘기는 표기 |
