지금까지 VPC를 구성하는 개별 요소(Subnet, Route Table, Internet Gateway, NAT Gateway, Security Group, NACL)를 하나씩 살펴봤다. [지난 글](/2026/09/21/aws-nacl/)에서 예고했던 "ALB·ASG 포함 전체 아키텍처 구성" 대신, 이번 글에서는 그 요소들을 실제로 배치할 때 — 특히 서브넷을 어떻게 나눌지 — 고려해야 할 설계 원칙을 먼저 정리한다.

## VPC 설계에서 고려할 두 가지

VPC를 구성할 때 신경 써야 할 지점은 크게 두 가지다.

- **VPC 간 IP 대역이 겹치지 않게 하기**: 나중에 다른 VPC나 다른 클라우드와 연결할 가능성을 열어두는 것
- **고가용성을 위한 서브넷·애플리케이션 티어 분배**: AZ와 Tier를 어떻게 나눌지

이번 글은 두 번째, 서브넷 분배를 중심으로 다룬다.

## IP 대역은 나중을 위해 겹치지 않게

VPC끼리 피어링을 하려면 서로의 CIDR이 겹치지 않아야 한다. 지금 당장은 VPC 하나로 시작하더라도, 나중에 계정이 늘어나거나 다른 리전에 VPC를 추가하거나 다른 클라우드와 연동하게 될 가능성이 있다. 이런 확장을 염두에 두고 처음부터 IP 대역이 서로 겹치지 않도록 설계해두는 게 좋다.

## 고가용성을 위한 AZ × Tier 구조

고가용성을 확보하려면 최소 3개 이상의 가용 영역(AZ)에 리소스를 분산해야 한다. 여기에 더해, 나중에 AZ를 하나 더 써야 할 상황을 대비해서 **예비 AZ 자리까지 미리 마련**해두는 게 좋다. 즉 AZ 3개 + 예비 1개, 총 4개 슬롯이다.

애플리케이션 티어도 비슷하게 생각할 수 있다. 흔히 말하는 3-Tier 아키텍처(Web, App, DB)에 마찬가지로 **예비 티어 자리**를 하나 더 남겨두면, 나중에 새로운 티어가 필요해졌을 때 전체 구조를 다시 짤 필요가 없다. Tier 3개 + 예비 1개, 역시 4개 슬롯이다.

## 실전 예시: 10.0.0.0/16을 16개의 /20으로 나누기

AZ 슬롯 4개 × Tier 슬롯 4개를 곱하면 정확히 16개의 서브넷이 필요하다는 계산이 나온다. `10.0.0.0/16`을 16개로 나누려면 호스트 비트에서 4비트를 서브넷 비트로 가져와야 한다(2⁴ = 16). `/16`에 4비트를 더하면 `/20`이 된다.

![10.0.0.0/16을 AZ × Tier 16칸으로 나눈 예시](/assets/images/aws-vpc-design/vpc_design_grid.png)

이렇게 나누면 AZ와 Tier의 조합마다 CIDR 블록이 하나씩 깔끔하게 떨어진다. 지금 당장 예비 AZ나 예비 Tier를 쓰지 않더라도, 자리를 미리 잡아두면 나중에 확장할 때 기존 서브넷 구성을 건드리지 않고 그 칸에 끼워 넣을 수 있다.

## 왜 /20인가: /24와 비교

서브넷 크기는 보통 `/20` 또는 `/24`로 나누는 경우가 많다.

- **`/24`**: 딱 떨어지는 숫자라 눈으로 보기 쉽다. `10.0.1.0`, `10.0.2.0`처럼 세 번째 옥텟이 그대로 서브넷 번호가 되기 때문에 익힐 때는 편하다.
- **`/20`**: 서브넷 하나당 쓸 수 있는 IP가 훨씬 많다(4,096개, 예약 5개를 빼도 4,091개). CIDR 표기에 익숙해지면 계산이 어렵지 않고, 실전에서는 이쪽을 더 많이 쓴다.

`/24`는 처음 연습할 때 눈에 잘 들어온다는 장점이 있을 뿐, IP가 부족해지기 쉬워서 실무에서는 `/20` 정도로 여유 있게 잡는 경우가 많다. 정답이 정해진 문제는 아니지만, 처음 설계할 때 기준을 못 잡겠다면 이 AZ × Tier 방식으로 `/20`부터 시작하는 게 무난하다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| **VPC 피어링 IP 겹침 금지** | 피어링하려는 VPC끼리는 CIDR 대역이 겹치면 안 됨 |
| **예비 AZ / 예비 Tier** | 지금 당장 쓰지 않아도 확장을 대비해 미리 마련해두는 슬롯 |
| **AZ × Tier 서브넷 설계** | 가용 영역과 애플리케이션 티어를 축으로 삼아 서브넷 개수를 정하는 방식 |
| **/20 서브넷** | 서브넷당 4,096개 IP(사용 가능 4,091개). 실전에서 자주 쓰는 크기 |
| **/24 서브넷** | 서브넷당 256개 IP. 옥텟이 그대로 서브넷 번호가 되어 연습용으로 보기 쉬움 |
