Linux 명령어를 연습하려면 마음대로 만지고 지워도 되는 서버가 필요하다. 이 글은 운영체제와 커널이 무엇인지 짚은 뒤, AWS Lightsail로 Ubuntu 서버를 준비하고, 접속한 터미널 화면을 읽는 방법까지 정리한다. 이어지는 두 편(경로와 파일 다루기, tar와 링크)은 모두 이 글에서 만든 서버에서 실습한다.

## 운영체제와 커널은 무슨 역할을 하는가

운영체제는 프로그램과 CPU, 메모리, 저장장치를 연결해 주는 소프트웨어다. 그 핵심이 **커널**이고, Linux는 이 커널의 이름이다. 커널은 여러 프로그램이 컴퓨터의 부품을 함께 쓸 수 있도록 일을 나누고 순서를 조율한다.

```text
실행 중인 프로그램 → Linux 커널 → CPU, 메모리, 디스크
```

프로그램이 파일을 읽거나 저장할 때도 직접 디스크에 접근하지 않고 커널에 작업을 요청한다. 이때 접근 권한 같은 조건에 따라 허용 여부가 갈린다. 그래서 명령어를 잘못 입력해서 실패한 경우와 파일에 접근할 권한이 없어서 실패한 경우는 원인이 전혀 다르다. 오류를 만났을 때 이 둘을 먼저 구분하면 원인을 훨씬 빨리 좁힐 수 있다.

Linux는 커널만으로 쓰지 않고, 필요한 프로그램과 도구를 묶어 **배포판**이라는 형태로 제공한다. Debian, Rocky Linux, Ubuntu가 대표적이다. 이 시리즈의 조합은 AWS라는 서비스 안에서 Lightsail로 서버를 빌리고, 그 서버의 운영체제로 Ubuntu를 쓰는 구성이다.

## Lightsail은 EC2와 무엇이 다른가

Lightsail은 서버를 간소화해서 준비해 주는 AWS 서비스다. 서버 사양, 저장 공간, 일정량의 데이터 전송량을 하나의 플랜으로 묶어 제공하고, 브라우저에서 서버에 바로 접속할 수 있다. EC2처럼 VPC, 보안 그룹, 스토리지를 각각 구성하지 않아도 되어 Linux 실습 환경을 빠르게 만들기에 알맞다.

| 비교 항목 | Lightsail | EC2 |
|---|---|---|
| 과금 방식 | 사양, 저장 공간, 전송량을 묶은 플랜 | 인스턴스, 스토리지, 전송량을 각각 과금 |
| 네트워크 구성 | 기본 제공되어 신경 쓸 부분이 적다 | VPC, 서브넷, 보안 그룹을 직접 설계 |
| 접속 | 브라우저에서 바로 SSH 접속 가능 | SSH 클라이언트나 Session Manager 등을 설정 |
| 적합한 용도 | 학습, 소규모 웹사이트 | 세밀한 구성이 필요한 운영 환경 |

### 블루프린트는 무엇을 고르는가

새 서버에 설치할 운영체제와 프로그램을 미리 준비해 둔 것을 **이미지** 또는 **블루프린트**라고 부른다. 선택 항목은 두 가지로 나뉜다.

| 항목 | 포함되는 것 | 언제 고르는가 |
|---|---|---|
| Linux apps | 운영체제 + WordPress 같은 프로그램까지 준비된 구성 | 특정 애플리케이션을 바로 쓰고 싶을 때 |
| Linux operating system | 운영체제만 설치된 구성 | 필요한 프로그램을 직접 설치하며 배울 때 |

실습에서는 프로그램을 직접 설치하는 흐름이므로 Linux operating system에서 Ubuntu를 고른다. 버전은 **LTS**(Long Term Support)를 선택한다. LTS는 일반 버전보다 오랜 기간 보안 업데이트와 유지보수를 제공하기 때문에, 같은 운영체제 버전을 오래 사용할 서버에 알맞다.

### 실습이 끝나면 인스턴스를 어떻게 정리하는가

Lightsail은 인스턴스를 중지해도 요금이 계속 발생한다. 사양과 저장 공간을 묶은 플랜이 계정에 계속 남아 있기 때문이다. 과금을 멈추려면 인스턴스를 삭제해야 한다. 작업 내용을 남기고 싶다면 스냅샷을 만들어 두고 인스턴스를 삭제하는 방법이 있고, 스냅샷은 실행 중인 인스턴스보다 저렴하다. 고정 IP 같은 부속 리소스가 남아 비용이 나가는 경우도 있으니, 정리할 때는 인스턴스만 보지 말고 콘솔에 남은 리소스를 함께 확인한다.

## IAM 정책은 무엇을 허용하는가

AWS 콘솔이나 CLI로 Lightsail을 다루는 사용자에게는 IAM 정책으로 권한을 준다. 정책은 이 사용자가 어떤 작업을 할 수 있는지 정해 둔 권한 규칙이다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "lightsail:*"
      ],
      "Resource": "*"
    }
  ]
}
```

`Action`의 `lightsail:*`는 Lightsail의 모든 작업을 뜻하고, `Resource`의 `*`는 이 권한을 특정 서버 한 대에만 제한하지 않았다는 뜻이다. 실습용으로는 편하지만, 운영 환경에서는 필요한 작업과 리소스만 허용하는 최소 권한 원칙에 따라 범위를 좁히는 것이 좋다.

## 접속하면 무엇이 보이는가

Lightsail 콘솔에서 인스턴스를 열고 브라우저 기반 SSH 접속 버튼을 누르면 터미널이 열린다. 처음 보이는 프롬프트는 다음과 같은 형태다.

```text
ubuntu@ip-172-26-x-x:~$
```

`사용자이름@호스트이름:현재위치$` 구조다. `ubuntu`는 지금 로그인한 사용자, `@` 뒤는 접속한 서버의 호스트 이름, `~`는 현재 위치가 홈 디렉터리라는 뜻이다. 일반 사용자 프롬프트는 `$`로 끝난다. 이 표시를 읽을 줄 알면 "내가 지금 누구로 어느 서버의 어느 폴더에 있는가"를 매번 눈으로 확인할 수 있다.

접속 직후 아래 세 가지를 실행해 서버 상태를 확인해 보자.

```bash
whoami          # 현재 사용자 이름
hostname        # 서버의 호스트 이름
uname -r        # 실행 중인 커널 버전
```

`uname -r`은 앞에서 설명한 커널의 버전을 직접 보여 준다. 배포판과 커널이 별개의 개념이라는 점을 실제 출력으로 확인하는 셈이다.

## 터미널, 셸, 커널은 각각 무엇을 맡는가

터미널 화면에서 일어나는 일은 네 역할로 나누어 이해하면 정리가 쉽다.

| 구성 요소 | 역할 |
|---|---|
| 터미널 | 입력과 출력을 보여 주는 창. 실제 일은 하지 않는다 |
| 셸 | 입력한 명령을 해석해 직접 처리하거나 필요한 프로그램을 실행한다 |
| 커널 | 프로그램이 자원을 쓰고 파일·장치에 접근하는 일을 관리한다 |
| 원격 서버 | 접속 후 명령이 실제로 실행되는 곳 |

명령이 이상하게 동작할 때는 "이 명령을 어느 컴퓨터에서, 어느 위치에서 입력했는가"를 먼저 확인한다. 내 PC의 터미널과 서버의 터미널은 화면이 비슷해도 전혀 다른 컴퓨터이기 때문이다.

## 명령어는 어떻게 읽고 사용법은 어디서 확인하는가

### 명령, 인수, 옵션을 구분한다

`cat /etc/os-release`에서 `cat`은 명령이고, 뒤에 붙은 `/etc/os-release`처럼 명령에 전달하는 값을 **인수**라고 한다. `cat -n /etc/os-release`의 `-n`은 **옵션**으로, 명령의 동작 방식을 바꾼다. 이 경우 출력에 줄 번호가 붙는다.

```bash
cat /etc/os-release
cat -n /etc/os-release
```

`/etc/os-release`는 운영체제 이름과 버전 정보가 들어 있는 파일이라, 접속한 서버가 어떤 배포판인지 확인할 때 가장 먼저 열어 본다. 이 서버가 Ubuntu LTS가 맞는지 여기서 확인할 수 있다.

### 사용법을 모를 때는 세 가지 방법이 있다

```bash
cat --help        # 대부분의 명령이 지원하는 간단한 도움말
help pwd          # bash에 내장된 명령의 도움말
man cat           # 더 자세한 설명서
```

`pwd`나 `cd`처럼 bash 셸 자체에 들어 있는 명령을 **내장 명령**이라고 부르고, 이런 명령은 `help 명령이름`으로 확인한다. `cat`처럼 별도 프로그램인 명령은 `man`으로 본다. 어느 쪽인지 헷갈리면 `type pwd`, `type cat`으로 종류를 확인할 수 있다.

`man`은 `less`와 같은 뷰어로 열리므로 조작 키도 같다.

| 키 | 동작 |
|---|---|
| `g` | 설명서의 맨 위로 이동 |
| `G` | 맨 아래로 이동 |
| `/검색어` | 검색 |
| `n` | 다음 검색 결과로 이동 |
| `q` | 종료 |

설명서가 길게 느껴져도 처음부터 읽을 필요는 없다. 옵션이 궁금하면 `/` 뒤에 옵션 이름을 입력해 해당 위치로 바로 이동하는 방식이 효율적이다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| 커널 | 프로그램이 CPU, 메모리, 디스크를 함께 쓰도록 자원을 관리하고 조율하는 운영체제의 중심부 |
| 배포판 | 커널에 필요한 프로그램과 도구를 묶어 제공하는 형태 (Debian, Rocky Linux, Ubuntu 등) |
| Lightsail | 사양, 저장 공간, 전송량을 묶은 플랜으로 서버를 간단히 준비하는 AWS 서비스 |
| 블루프린트 | Lightsail에서 서버에 설치할 운영체제와 프로그램을 미리 준비해 둔 이미지 |
| LTS | Long Term Support. 일반 버전보다 오랜 기간 보안 업데이트와 유지보수를 제공하는 버전 |
| IAM 정책 | 사용자가 어떤 작업을 할 수 있는지 정해 둔 권한 규칙 |
| 터미널 | 명령을 입력하고 결과를 보여 주는 화면 |
| 셸 | 입력한 명령을 해석해 처리하거나 필요한 프로그램을 실행하는 프로그램 (bash 등) |
| 내장 명령 | 셸 자체에 들어 있는 명령 (`pwd`, `cd` 등). `help`로 확인 |
| 인수 | 명령에 전달하는 값 (파일이나 폴더 경로 등) |
| 옵션 | 명령의 동작 방식을 바꾸는 값 (`-n`, `-l`, `-r` 등) |
