지금까지는 명령의 실행 결과를 터미널 화면에서 읽었다. 화면은 스크롤이 지나가면 사라지고, 정상 결과와 오류가 섞여 있으면 어느 쪽이 무엇인지 구분하기도 어렵다. 이 글은 실행 결과를 파일로 남기는 리다이렉션을 정리한다. 정상 처리 결과와 오류 안내를 서로 다른 파일에 보관하는 방법, 새로 쓰기(`>`)와 이어 쓰기(`>>`)의 차이, 파일 내용을 명령의 입력으로 넘기는 `<`, 그리고 줄 수를 세는 `wc`를 다룬다. 실습은 `~/linux-lab/redirect-lab`에서 진행한다.

## 입력, 출력, 오류는 서로 다른 통로다

프로그램은 데이터를 주고받는 기본 통로를 세 개 가지고 있다. 입구와 출구, 그리고 문제 발생을 알리는 별도 출구로 이해하면 쉽다.

| 이름 | 번호 | 역할 | 기본 연결 대상 |
|---|---|---|---|
| 표준 입력 (stdin) | 0 | 프로그램이 재료를 받아들이는 입구 | 키보드 |
| 표준 출력 (stdout) | 1 | 처리한 정상 결과를 내보내는 출구 | 터미널 화면 |
| 표준 오류 (stderr) | 2 | 문제가 생겼다는 안내를 내보내는 별도 출구 | 터미널 화면 |

기본 상태에서는 표준 출력과 표준 오류가 모두 같은 터미널 화면에 나타나기 때문에 한 덩어리처럼 보인다. 하지만 실제로는 서로 다른 통로이고, 각각 다른 곳으로 보낼 수 있다. **입력을 받을 곳이나 출력을 내보낼 곳을 바꾸는 것을 리다이렉션**이라고 한다.

> `>`, `>>`, `2>`, `<`는 명령어의 옵션이 아니라 **셸이 처리하는 문법**이다. `cat`이나 `head`는 출력이 어디로 가는지 알지 못하고, 셸이 명령을 실행하기 전에 통로를 바꿔 연결해 준다.

## 정상 출력을 파일로 보내려면 어떻게 하는가

### 새로 쓰기: `>`

```bash
head -n 3 ../notes/day1.txt > report.txt
```

`head`가 표준 출력으로 내보내는 앞쪽 3줄이 화면 대신 `report.txt`에 저장된다. 화면에는 아무것도 나타나지 않지만 결과는 파일에 있다. 조용한 화면에서 "아무 일도 없었다"고 판단하지 말고 `cat report.txt`나 `ls -l`로 확인한다.

### 이어 쓰기: `>>`

```bash
tail -n 3 ../notes/day1.txt >> report.txt
```

꺾쇠를 두 개 이어 쓰면 기존 내용을 지우지 않고 파일 끝에 출력을 덧붙인다. 위 두 명령을 차례로 실행하면 `report.txt`에는 앞 3줄과 끝 3줄이 모두 들어 있다.

| 구분 | 기호 | 파일이 없을 때 | 파일에 이미 내용이 있을 때 |
|---|---|---|---|
| 새로 쓰기 | `>` | 새 파일을 만든다 | 기존 내용을 지우고 새로 쓴다 |
| 이어 쓰기 | `>>` | 새 파일을 만든다 | 기존 내용 뒤에 덧붙인다 |

저장할 파일이 아직 없으면 두 방식 모두 새 파일을 만든다. 차이는 이미 내용이 있을 때 드러난다.

### `>`는 명령이 실행되기 전에 파일을 비운다

새로 쓰기는 명령이 시작되기 전에 셸이 먼저 대상 파일을 비운다. 그래서 **읽을 원본을 저장할 파일로 지정하면 원본이 사라진다.** 복사본으로 직접 확인해 볼 수 있다.

```bash
cp ../notes/day1.txt tmp.txt
sort tmp.txt > tmp.txt      # 원본과 저장 대상이 같다
wc -l tmp.txt               # 0 tmp.txt
```

`sort`가 파일을 읽기 시작할 때는 이미 `tmp.txt`가 비어 있어서 결과가 빈 파일이 된다. 반드시 복사본으로만 실험하고, 실제 작업에서는 읽을 파일과 저장할 파일의 경로가 다른지 확인한다. 셸의 `set -o noclobber` 설정을 켜면 기존 파일에 `>`로 덮어쓰는 것을 막을 수 있고, 일부러 덮어쓸 때는 `>|`를 쓴다.

## 오류 메시지는 왜 파일에 저장되지 않는가

`>`로 출력을 파일에 보냈는데도 화면에 오류가 나타나는 경우가 있다.

```bash
cat missing.txt > out.txt
# cat: missing.txt: No such file or directory   ← 화면에 나온다
ls -l out.txt                                   # 크기 0인 빈 파일이 생겼다
```

`>`는 번호 1번인 표준 출력만 옮기기 때문이다. 오류 메시지는 번호 2번 통로로 나오므로 따로 지정해야 한다. 여기서 중요한 점이 두 가지 있다.

- 정상 출력이 없어도 `out.txt`라는 **빈 파일은 생긴다.** 파일이 생겼다는 사실만으로 명령이 성공했다고 판단하면 안 된다.
- 오류 메시지는 계속 화면에 나올 수 있으므로, 오류가 안 보이는 것과 성공은 다르다.

### 오류만 파일로 보내기: `2>`

```bash
cat missing.txt 2> errors.txt
cat errors.txt
# cat: missing.txt: No such file or directory
```

`2>`는 표준 오류를 `errors.txt`로 보낸다. 없는 파일이 생기거나 문제가 해결된 것이 아니라, **오류를 내보낼 위치만 바뀐 것**이다. 이렇게 남겨 두면 화면이 지나간 뒤에도 오류를 다시 읽을 수 있다. 숫자 `2`와 `>` 사이에는 공백을 넣지 않아야 한다. 공백을 넣으면 `2`가 명령의 인수로 해석된다.

### 정상 출력과 오류를 각각 다른 파일에 저장하기

```bash
cat ../notes/day1.txt missing.txt > output.txt 2> errors.txt
```

읽을 수 있는 메모와 존재하지 않는 파일을 함께 지정해 결과와 오류를 구분해서 받는 방법이다. `output.txt`에는 `day1.txt`의 내용이, `errors.txt`에는 `missing.txt`에 대한 오류가 들어간다. 같은 명령에서 나온 결과라도 통로를 구분하면 필요한 자료와 문제 원인을 나누어 보관할 수 있다. 오류를 계속 덧붙이고 싶을 때는 `2>>`를 쓴다.

## 현업에서는 리다이렉션을 어디에 쓰는가

### 정기 실행 스크립트의 로그를 남길 때

화면이 없는 곳(cron, 백그라운드 실행)에서 도는 작업은 출력이 갈 곳이 없으므로 파일로 남겨야 한다.

```bash
# 매일 새벽 3시에 백업 스크립트를 실행하고 정상 출력과 오류를 한 파일에 이어 쓴다
0 3 * * * /opt/backup.sh >> /var/log/backup.log 2>&1

# 터미널을 닫아도 계속 실행되게 하고 결과를 파일로 받는다
nohup ./server.sh > server.log 2>&1 &
```

`2>&1`은 "표준 오류(2)를 표준 출력(1)이 가는 곳으로 보낸다"는 뜻이다. **순서가 중요하다.** `> out.log 2>&1`은 출력을 파일로 보낸 뒤 오류도 같은 곳으로 보내지만, `2>&1 > out.log`는 오류가 먼저 화면(당시 출력 위치)에 연결되어 파일에는 정상 출력만 들어간다. bash에서는 `&> out.log`로 줄여 쓸 수도 있다.

### 필요 없는 오류를 버릴 때

`/dev/null`은 받은 내용을 모두 버리는 특수한 파일이다. 권한 오류가 잔뜩 나오는 검색이나 확인용 명령에서 오류만 버리고 싶을 때 쓴다.

```bash
find / -name 'nginx.conf' 2>/dev/null    # 접근 권한이 없는 폴더의 오류를 버린다
```

다만 오류를 통째로 버리면 진짜 문제도 보이지 않으므로, 오류를 버려도 되는 이유가 분명할 때만 쓴다.

### 화면에도 보면서 파일에도 저장할 때

`tee`는 입력받은 내용을 화면에 출력하면서 동시에 파일에 저장한다. 파이프(`|`)와 함께 쓰며, 파이프는 다음 글에서 자세히 다룬다.

```bash
ls -l | tee list.txt        # 화면에 보여 주고 list.txt에도 저장
ls -l | tee -a list.txt     # -a: 이어 쓰기
```

### `sudo`와 리다이렉션을 함께 쓸 때 막히는 이유

```bash
sudo echo "setting=1" > /etc/myapp.conf       # Permission denied
echo "setting=1" | sudo tee /etc/myapp.conf   # 동작한다
```

`>`는 `sudo`가 아니라 **현재 사용자의 셸**이 처리한다. 그래서 `echo`는 관리자 권한으로 실행되어도, 파일을 여는 일은 일반 권한으로 수행되어 거부된다. `sudo tee`를 쓰면 파일에 쓰는 프로그램 자체가 관리자 권한으로 실행된다. 리다이렉션이 명령의 일부가 아니라 셸의 문법이라는 점을 보여 주는 대표적인 사례다.

## 파일 내용을 명령의 입력으로 넘기려면 어떻게 하는가

프로그램이 데이터를 받아들이는 기본 통로가 표준 입력(번호 0)이다. `<`는 파일의 내용을 표준 입력으로 보낸다.

### `wc`로 줄 수를 세 보기

`wc`는 줄 수, 단어 수, 바이트 수를 세는 명령이다.

```bash
wc -l ../notes/day1.txt
# 12 ../notes/day1.txt

wc -l < ../notes/day1.txt
# 12
```

`-l`은 줄바꿈 문자의 수를 센다. 두 결과 모두 줄 수는 12로 같지만 표시 형식이 다르다.

- 첫 번째 명령은 **파일 경로를 인수로 전달**했기 때문에 `wc`가 파일 이름을 알고 결과에 함께 출력한다.
- 두 번째 명령은 `<`로 **파일 내용을 표준 입력에 넣어 주었기 때문에** `wc`는 어떤 파일인지 알지 못한다. 그래서 숫자만 출력한다.

`cat`처럼 본문 전체를 보여 주는 대신 개수만 알려 주는 명령이므로, 긴 파일의 규모를 확인할 때 편하다. 숫자만 필요한 스크립트에서는 `<` 형태가 후처리하기 좋다.

`-l`은 줄 끝의 줄바꿈 문자를 세므로, 마지막 줄에 줄바꿈이 없으면 그 줄은 세지 않는다. 다른 옵션도 함께 알아 둔다.

| 옵션 | 세는 대상 |
|---|---|
| `-l` | 줄 수(줄바꿈 문자) |
| `-w` | 단어 수 |
| `-c` | 바이트 수 |

## 실행했다는 것과 성공했다는 것은 어떻게 구분하는가

오류 메시지를 파일로 옮겨도 오류의 원인이 해결되는 것은 아니다. 파일이 만들어졌다는 사실만 보지 말고 내용을 확인해야 한다. 성공 여부는 세 가지로 확인한다.

1. **파일 내용**: `cat output.txt`, `cat errors.txt`로 각각 무엇이 들어갔는지 본다.
2. **파일 크기**: `ls -l`에서 `errors.txt`가 0바이트가 아니면 오류가 기록된 것이다.
3. **종료 상태**: 명령이 끝난 직후 `echo $?`를 실행하면 방금 명령의 종료 상태가 나온다. 0이면 성공이고, 0이 아니면 실패다.

```bash
cat missing.txt 2> errors.txt
echo $?        # 1
```

## 실습 순서와 폴더 준비

```bash
mkdir -p ~/linux-lab/redirect-lab
cd ~/linux-lab/redirect-lab
pwd            # /home/ubuntu/linux-lab/redirect-lab 인지 확인
```

앞 편에서 만든 `~/linux-lab/notes/day1.txt`가 있다면 `../notes/day1.txt`로 그대로 쓴다. 파일이 없다면 12줄짜리 연습 파일을 만들어 쓴다(`>` 새로 쓰기이므로 기존 파일이 없을 때만 실행한다).

```bash
mkdir -p ../notes
for i in $(seq 1 12); do echo "memo line $i"; done > ../notes/day1.txt
```

이 글의 예시는 모두 파일이 12줄이라는 가정이다. 줄 수가 다르면 `wc -l` 결과도 달라진다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| 표준 입력 (stdin, 0) | 프로그램이 데이터를 받아들이는 기본 통로 |
| 표준 출력 (stdout, 1) | 프로그램이 정상 처리 결과를 내보내는 기본 통로 |
| 표준 오류 (stderr, 2) | 프로그램이 오류 안내를 내보내는 별도 통로 |
| 리다이렉션 | 입력을 받을 곳이나 출력할 곳을 바꾸는 셸의 문법 |
| `>` | 표준 출력을 파일에 새로 쓴다. 기존 내용은 지워진다 |
| `>>` | 표준 출력을 파일 끝에 이어 쓴다 |
| `2>` | 표준 오류를 파일에 보낸다 |
| `2>&1` | 표준 오류를 표준 출력이 가는 곳으로 보낸다 |
| `<` | 파일 내용을 표준 입력으로 보낸다 |
| `/dev/null` | 받은 내용을 모두 버리는 특수 파일 |
| `tee` | 입력을 화면에 보여 주면서 파일에도 저장하는 명령 |
| 종료 상태 | 명령이 끝났을 때 남기는 숫자. 0이면 성공, `echo $?`로 확인 |
| `wc` | 줄 수, 단어 수, 바이트 수를 세는 명령 |
