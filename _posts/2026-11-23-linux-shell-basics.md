터미널에서는 글자로 표시된 경로를 보며 현재 위치와 파일의 위치를 확인한다. 이 글은 Ubuntu 서버에서 폴더를 오가며 "내가 있는 곳"과 "작업할 파일이 있는 곳"을 구분하는 방법, 그리고 파일과 폴더를 만들고 복사하고 옮기고 지우고 읽고 편집하는 기본 명령어를 정리한다. 서버 준비와 접속은 이전 글에서 마쳤다고 가정한다. 모든 명령은 입력하기 전에 "어느 컴퓨터에서, 어느 폴더에서 실행하는가"를 먼저 확인하고 사용한다.

## 절대 경로와 상대 경로는 무엇이 다른가

경로는 파일과 폴더의 위치를 글자로 적은 것이다. 집 주소로 알려 줄지, 지금 서 있는 곳에서 가는 길을 알려 줄지의 차이로 이해하면 쉽다.

| 구분 | 비유 | 시작점 | 예시 | 특징 |
|---|---|---|---|---|
| 절대 경로 | 집 주소 | 루트(`/`) | `/home/ubuntu` | 어디서 입력해도 같은 곳을 가리킨다 |
| 상대 경로 | 여기서 가는 길 | 현재 위치 | `ubuntu` (현재 위치가 `/home`일 때) | 출발점이 달라지면 도착점도 달라진다 |

맨 앞이 `/`로 시작하면 루트부터 적은 절대 경로이고, 그렇지 않으면 현재 위치 기준의 상대 경로다. 상대 경로에서는 특수한 이름 두 가지를 자주 쓴다.

- `./파일이름`: 현재 폴더 안에서 찾는다.
- `../파일이름`: 한 단계 위 폴더에서 찾는다.

"파일을 못 찾겠다"는 상황에서는 파일이 사라진 것인지, 내가 다른 폴더에 있는 것인지부터 구분해야 한다. `pwd`로 현재 위치를 확인하는 습관이 이 구분을 도와준다.

## 자주 쓰는 디렉터리와 담기는 자료

Linux의 폴더(디렉터리)는 맨 위의 루트 `/`에서 나뭇가지처럼 이어진다. 서버를 다루다 보면 자주 들르는 위치가 정해져 있다.

| 경로 | 담기는 것 | 주의할 점 |
|---|---|---|
| `/home` | 사용자들의 홈 폴더가 모인 상위 위치 | 내 작업 공간은 `/home/ubuntu`처럼 그 아래에 있다 |
| `/etc` | 시스템과 여러 프로그램의 설정 파일 | 내용을 바꾸면 동작에 영향을 줄 수 있다 |
| `/var` | 로그나 운영 중 사용하는 데이터처럼 시간이 지나며 달라지는 자료 | |
| `/var/log` | 프로그램이 한 일과 발생한 문제를 남긴 로그 | 서버 상태를 확인할 때 가장 먼저 본다 |
| `/tmp` | 프로그램이 잠시 쓰는 임시 자료 | 정리 정책에 따라 지워질 수 있어 오래 보관할 파일에는 부적합 |

## 위치를 확인하고 이동하는 명령어: pwd, cd, ls

### pwd로 현재 위치를 확인한다

`pwd`(Print Working Directory)는 지금 들어와 있는 폴더를 보여 준다. 폴더를 바꾸거나 파일을 수정하지 않으므로 파일 작업 전에 부담 없이 습관처럼 입력해도 된다.

```bash
pwd
```

### cd로 작업 폴더를 이동한다

`cd`는 작업 위치를 바꾼다. 이후 파일 이름만 적으면 이동한 폴더 안에서 찾는다.

```bash
cd /etc      # 절대 경로로 이동
cd ubuntu    # 상대 경로로 이동 (현재 위치가 /home일 때)
cd           # 홈 디렉터리로 이동
cd ~         # 홈 디렉터리로 이동 (위와 동일)
cd ..        # 한 단계 위 폴더로 이동
cd .         # 현재 폴더 유지
cd -         # 직전에 있던 폴더로 이동 (이동한 경로도 함께 출력)
```

`..`는 지금 폴더를 담고 있는 바깥 폴더이고, `-`는 이동하기 직전에 있던 폴더다. 두 가지는 비슷해 보여도 다르다. 예를 들어 `/etc`에서 `/var/log`로 이동한 뒤 `cd ..`를 하면 `/var`로, `cd -`를 하면 `/etc`로 간다.

### ls로 목록을 확인한다

`ls`는 폴더 안의 파일과 폴더 목록을 보여 준다. 경로를 쓰지 않으면 현재 폴더를, 쓰면 그 폴더를 본다.

```bash
ls
ls /etc
```

여기서 중요한 구분이 하나 있다. **`cd`는 작업 위치를 바꾸고, `ls`는 지정한 곳의 목록만 보여 준다.** `ls /etc`를 실행해도 내 위치는 그대로다.

## 실습 작업 공간 만들기

실습 폴더를 직접 만들 때는 `mkdir`과 `touch`를 쓴다. 이 명령들은 성공해도 화면에 아무 메시지가 나오지 않는 경우가 많다. 아무 일도 없었다고 생각하지 말고 `ls`로 새 항목이 생겼는지 확인한다.

### mkdir로 폴더를 만든다

```bash
mkdir notes                    # 폴더 하나 생성
mkdir 폴더1 폴더2 폴더3        # 띄어 쓰면 각각 생성
mkdir -p data/raw              # 중간 폴더까지 함께 생성
```

`-p`는 경로 중간에 필요한 폴더가 없으면 함께 만들고, 이미 있는 폴더는 그대로 둔다. 예시의 `raw`는 가공하기 전 원본 자료를 모아 두는 폴더 이름으로 흔히 쓴다.

### touch로 빈 파일을 만든다

```bash
touch notes/day1.txt
touch .practice
```

빈 파일은 크기가 0이어도 존재하는 파일이다. 같은 이름의 파일이 이미 있으면 내용을 지우지 않고 시간 정보만 갱신한다. 주의할 점은 `touch`가 중간 폴더까지 만들어 주지는 않는다는 것이다. `notes` 폴더가 없는 상태에서 `touch notes/day1.txt`를 실행하면 실패하므로 폴더를 먼저 준비해야 한다.

### 파일 이름에서 알아둘 점

- 이름은 대문자와 소문자를 구분한다. `Memo`와 `memo`는 서로 다른 이름이다.
- 확장자(`.txt` 등)는 파일의 용도를 짐작하게 해 주는 이름표다. 확장자가 없어도 파일을 만들 수 있고, 이름만 바꾼다고 내용의 형식이 바뀌지도 않는다.
- 이름이 `.`으로 시작하면 숨김 파일이다. 기본 목록에서 생략될 뿐, 암호화하거나 다른 사용자의 접근을 막는 기능은 아니다.
- 파일을 만들기 위해 그 폴더로 먼저 이동할 필요는 없다. 현재 위치에서 저장할 경로를 지정해도 된다.

### ls 옵션으로 목록을 자세히 본다

```bash
ls -1             # 한 줄에 한 항목씩
ls -l             # 권한, 소유자, 크기 등 상세 정보
ls -la            # 숨김 항목까지 포함한 상세 목록
ls -ld ~/linux-lab   # 폴더 안이 아닌 폴더 자체의 정보
ls -A restore-lab    # 숨김 항목 포함, 단 . 과 .. 는 제외
ls -lh archive-lab   # 크기를 K, M 단위로 읽기 쉽게
ls -R restore-lab    # 하위 폴더 안쪽까지 재귀적으로
```

`-l`과 `-a`는 `-la`처럼 합쳐 쓸 수 있다. `-a`는 `.`(현재 폴더)와 `..`(상위 폴더)까지 보여 주지만, `-A`는 이 둘을 제외하므로 실제 숨김 파일만 확인하기 좋다.

### ls -l 출력 읽기

```text
drwxrwxr-x 2 ubuntu ubuntu 4096 Nov 21 10:00 notes
-rw-rw-r-- 1 ubuntu ubuntu    0 Nov 21 10:01 day1.txt
```

맨 앞 글자는 항목의 종류를 나타낸다. `d`는 디렉터리, `-`는 일반 파일, `l`은 심볼릭 링크다(링크는 다음 글에서 다룬다). 이어지는 아홉 글자는 소유자, 그룹, 그 외 사용자의 읽기(`r`)·쓰기(`w`)·실행(`x`) 권한이다.

목록 맨 위에 나오는 `total` 값은 읽을 때 주의가 필요하다.

- 목록에 표시된 항목들에 **할당된 디스크 공간의 합계**다. 파일 개수가 아니다.
- 내용이 없는 빈 파일만 있다면 할당된 데이터 공간이 없어 `total 0`으로 나온다. 이 경우에도 파일 이름 같은 관리 정보가 디스크를 전혀 쓰지 않는다는 뜻은 아니다.
- 하위 폴더의 내용까지 모두 더한 값도 아니다.

따라서 파일의 존재와 개수는 아래 항목들을 보고 확인하고, `total`은 디스크 사용량 정보로 구분해서 읽는다. 디스크는 공간을 일정한 블록 단위로 할당하기 때문에, 파일 내용의 크기와 실제 할당된 공간은 다를 수 있다. 예를 들어 377바이트 파일이 있는 목록의 `total`이 `4.0K`로 나오는 것이 그런 경우다.

## 복사, 이동, 삭제는 무엇이 남고 무엇이 바뀌는가

세 명령의 차이는 문서를 다루는 방식으로 비유할 수 있다. 복사는 문서를 한 장 더 만드는 일이라 원본과 복사본이 따로 남는다. 이동은 문서를 다른 서랍으로 옮기는 일이라 이전 자리에는 남지 않는다. 같은 폴더에서 새 이름을 지정해 이동하면 이름만 바뀐다. 삭제는 보통 휴지통을 거치지 않으므로 되돌리기 어렵다.

| 명령 | 원본 | 새 위치 | 되돌리기 |
|---|---|---|---|
| `cp` | 그대로 남는다 | 복사본이 생긴다 | 복사본만 지우면 된다 |
| `mv` | 이전 자리에서 사라진다 | 같은 파일이 놓인다 | 다시 `mv`로 돌려놓는다 |
| `rm` | 사라진다 | 없음 | 보통 불가능하다 |

### cp로 원본을 남기고 복사한다

```bash
cp todo.txt todo-copy.txt              # 파일을 새 이름으로 복사
cp report-*.txt archive/               # 패턴에 맞는 파일을 폴더로 복사
cp -r notes file-ops/notes-copy        # 폴더를 내용까지 복사
cp -i 원본 목적지                      # 덮어쓰기 전에 확인
cp tasks.txt "meeting notes.txt"       # 공백이 있는 이름은 따옴표로 묶기
```

원본을 먼저, 새로 둘 위치나 이름을 마지막에 쓴다. 받는 곳이 기존 폴더이면 그 안에 복사된다. `-r`은 폴더 안의 항목까지 함께 복사하라는 옵션이다. `cp`를 실행하기 전에 가장 먼저 할 일은 원본과 목적지를 정확하게 적는 것이다.

### mv로 옮기거나 이름을 바꾼다

```bash
mv todo-copy.txt archive/      # archive 폴더로 이동
mv todo.txt tasks.txt          # 같은 폴더에서 이름 변경
```

`mv`는 "이동"과 "이름 변경"이 같은 명령이다. 목적지가 기존 폴더이면 이동이고, 새 이름이면 이름 변경이다. 같은 이름의 파일이 이미 있으면 덮어써질 수 있으므로 먼저 확인한다.

### rm으로 삭제한다

```bash
rm -i "meeting notes.txt"      # 확인을 받고 삭제
rm -r notes-copy               # 폴더와 내부 항목 삭제
```

`-i`는 각 삭제 전에 확인 질문을 하고, `-r`은 폴더 안의 항목까지 함께 지운다. 확인 질문에 나온 파일 이름을 눈으로 살펴본 뒤 연습용 복사본만 지워지는지 확인한다.

### 와일드카드는 먼저 목록으로 확인한다

`ls -l report-*.txt`에서 `*`는 이름의 일부를 비워 두고 0개 이상의 글자와 맞추는 **와일드카드**다. 여러 파일을 한 번에 고를 수 있어 편하지만, 예상보다 많은 파일이 선택될 위험이 있다.

그래서 복사·이동·삭제에 와일드카드를 쓰기 전에는 같은 패턴으로 `ls`를 먼저 실행해 대상 목록을 확인한다. 패턴은 실행하는 시점에 존재하는 이름을 기준으로 해석되므로, 대상이 달라질 수 있는 상황에서는 예전에 확인한 목록만 믿고 실행하지 않는다.

```bash
ls -l report-*.txt     # 1단계: 어떤 파일이 선택되는지 먼저 확인
cp report-*.txt archive/   # 2단계: 같은 패턴으로 실행
```

이름에 공백이 있는 파일은 셸이 공백을 여러 파일의 구분자로 해석하기 때문에 따옴표로 묶어야 한다. 처음부터 공백이 없는 이름(`meeting-notes.txt`)을 쓰면 이런 번거로움을 피할 수 있다.

## 파일 내용 읽기와 편집

텍스트 파일은 글자 크기나 색 같은 서식 없이 글자 자체만 담는다. 서버에서는 프로그램의 설정과 실행 기록을 이런 파일에 적는다. 내용 길이에 따라 읽는 도구를 고른다.

| 명령 | 보여 주는 범위 | 쓰는 상황 |
|---|---|---|
| `cat` | 전체를 한꺼번에 | 짧은 메모, 설정 파일 |
| `head -n 3` | 앞쪽 3줄 | 긴 로그의 형식 확인 |
| `tail -n 3` | 끝쪽 3줄 | 새 기록이 아래에 쌓이는 로그의 최근 내용 확인 |
| `less` | 페이지 단위로 넘기며 | 긴 문서 |

```bash
cat -n notes/day1.txt       # 줄 번호를 붙여 출력
head -n 3 notes/day1.txt
tail -n 3 notes/day1.txt
less notes/day1.txt         # / 검색, n 다음 결과, q 종료
```

이 읽기 명령들은 파일 내용을 바꾸지 않는다. `cat -n`의 줄 번호도 화면 출력에만 붙을 뿐 파일에 저장되지 않는다.

### nano 편집과 저장 순서

`nano`는 터미널 안에서 글을 쓰고 고칠 수 있는 텍스트 편집기다. 파일을 수정하려면 그 파일에 쓸 수 있는 권한이 있어야 한다.

```bash
nano notes/day1.txt
```

편집기 안에서는 명령을 입력하던 터미널과 조작 방법이 다르다. 화면에서 내용을 고쳐도 저장하기 전에는 파일에 반영되지 않는다.

1. 내용을 수정한다.
2. `Ctrl + O`를 누르고, 화면에 표시된 저장할 파일 이름을 확인한 뒤 `Enter`를 누른다.
3. `Ctrl + X`로 편집기를 나온다.
4. `cat -n notes/day1.txt`로 파일을 다시 열어 수정 내용이 들어 있는지 확인한다.

저장 여부를 눈으로 믿지 않고 파일을 다시 읽어 확인하는 것이 핵심이다. 서버의 설정 파일을 편집할 때도 같은 절차를 따르면 실수를 줄일 수 있다.

## 실습 전에 확인하는 습관

이 글의 명령어를 한꺼번에 순서대로 실행하지 않는다. 입력하기 전에 두 가지를 확인한다. 이 명령을 **어느 컴퓨터**에서 실행하는가, 그리고 **현재 폴더**가 어디인가. `pwd`와 `ls`로 위치와 대상을 확인한 뒤 복사·이동·삭제를 실행하고, 실행 후에는 원래 자리와 새 자리를 다시 `ls`로 비교한다. 삭제는 특히 되돌리기 어려우므로 `-i` 옵션과 연습용 복사본을 활용한다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| 디렉터리 | 폴더를 뜻하는 Linux 용어. 맨 위의 루트(`/`)에서 나뭇가지처럼 이어진다 |
| 절대 경로 | 루트(`/`)부터 적는 전체 위치. 어디서 입력해도 같은 곳을 가리킨다 |
| 상대 경로 | 현재 위치를 기준으로 적는 위치. 출발점이 달라지면 도착점도 달라진다 |
| 홈 디렉터리 | 사용자 개인 작업 공간 (`~`, `/home/ubuntu`) |
| 현재 작업 디렉터리 | 지금 들어와 있는 폴더. `pwd`로 확인 |
| 숨김 파일 | 이름이 `.`으로 시작해 기본 목록에서 생략되는 파일. 접근을 막는 기능은 아님 |
| 확장자 | 파일 이름 끝의 `.txt` 같은 부분. 용도를 짐작하게 하는 이름표일 뿐 내용 형식을 바꾸지 않음 |
| 와일드카드 | `*`처럼 이름의 일부를 대신해 여러 파일을 고르는 기호 |
| 덮어쓰기 | 같은 이름의 파일이 있는 곳에 쓰면서 기존 내용이 바뀌는 일 |
| 로그 | 프로그램이 한 일과 발생한 문제를 남긴 기록 (`/var/log`) |
| 텍스트 파일 | 서식 없이 글자 자체만 담은 파일. 설정과 로그에 쓰임 |
| nano | 터미널 안에서 글을 쓰고 고칠 수 있는 텍스트 편집기 |
