[VPC 파트](/2026/09/26/aws-vpc-recap/)를 마치고 이번 글부터 **Amazon S3**를 다룬다. 첫 글에서는 S3가 어떤 서비스인지, 오브젝트 스토리지가 파일 스토리지와 어떻게 다른지, 그리고 왜 필요한지를 정리한다.

## Amazon S3: 객체 스토리지 서비스

Amazon S3(Simple Storage Service)는 확장성, 데이터 가용성, 보안, 성능을 갖춘 **오브젝트 스토리지 서비스**다. 이름에 S가 세 개 들어가서 흔히 S3라고 부른다. AWS는 99.999999999%(9가 11개, 흔히 "일레븐 나인")의 내구성을 제공하도록 설계됐다고 소개한다. 강사는 AWS에서 가장 중요한 서비스 세 개로 EC2, Lambda, S3를 꼽았는데, 그만큼 거의 모든 아키텍처에서 만나게 되는 서비스다.

## 파일 스토리지 vs 오브젝트 스토리지

S3를 이해하려면 먼저 두 스토리지 방식의 차이를 알아야 한다.

| 구분 | 파일 스토리지 | 오브젝트 스토리지 |
|---|---|---|
| 관리 단위 | 파일을 계층(폴더) 구조로 관리 | 데이터, 메타데이터, ID로 이뤄진 오브젝트 |
| 접근 방식 | 탐색하며 빠르게 찾고 수정 가능 | 정확한 경로(키)를 알아야 접근 |
| 확장성 | 제한적 (수십 TB 수준) | 매우 쉬움 (수십 PB 이상) |
| 대표 예시 | 내 PC의 HDD/SSD | S3, 웹하드, 구글 드라이브 |

간단하게 구분하는 방법은 이렇다. 그 위에 게임을 설치해서 실행할 수 있으면 파일 스토리지(내 컴퓨터의 SSD처럼)고, 파일을 올리고 내려받을 수만 있고 설치해서 실행할 수는 없으면 오브젝트 스토리지다.

## 언제 S3를 쓰는가

AWS에서 파일을 저장하거나 활용해야 한다면 가장 먼저 S3를 떠올리면 된다. 이미지·영상 같은 미디어, 로그 파일, 소스코드, 백업 파일 등 종류를 가리지 않는다. 오히려 S3를 쓰지 않을 이유를 찾아야 할 정도로 활용도가 높다. 저장 외에도 두 가지 용도가 있다.

- **정적 웹 호스팅**: 서버 없이(서버리스) 웹페이지를 제공할 수 있다
- **파일 관리**: 파일 공유, 버전 관리 등 다양한 관리 기능을 쓸 수 있다

## 왜 필요한가: EC2마다 파일을 저장하면 생기는 문제

로드밸런서 뒤에 EC2가 여러 대 있고, 웹페이지에 쓰는 이미지와 영상을 각 EC2(정확히는 EBS)에 저장한다고 해보자.

![EC2마다 저장하는 구조와 S3에 통합 저장하는 구조 비교](/assets/images/aws-s3-intro/s3_shared_storage.png)

이 구조에는 두 가지 문제가 있다. 첫째, **같은 파일이 서버 수만큼 중복 저장**된다. 파일이 수 GB일 수 있고 서버가 수십~수백 대로 늘어날 수 있으니 용량 낭비가 크다. 둘째, **파일 하나를 교체하려면 모든 서버를 일일이 수정**해야 한다.

콘텐츠 파일을 S3에 저장하면 이 문제가 풀린다. 각 EC2에는 소스코드 같은 꼭 필요한 코어 파일만 두고, 이미지·영상 같은 콘텐츠는 S3 한 곳에 모아둔다. 용량이 줄어들고, S3의 파일을 교체하면 모든 웹서버에 동시에 반영된다. 분산된 아키텍처에서 파일을 하나로 통합하는 역할이 S3다.

## 내구성과 가용성은 다르다

S3는 99.999999999%의 **내구성**과 99.99%의 **가용성**을 가진 분산 스토리지에 파일을 저장한다. 이 둘은 서로 다른 개념이다.

| 구분 | 의미 | S3 수치 |
|---|---|---|
| 내구성(Durability) | 파일을 잃어버리지 않을 능력 | 99.999999999% |
| 가용성(Availability) | 내가 원할 때 파일을 가져올 수 있는 능력 | 99.99% |

한 번 올린 파일이 사라질 일은 사실상 없지만, 아주 드물게 원하는 순간에 접근하지 못할 수는 있다는 뜻이다. 가용성도 낮은 수치가 아니라서 S3는 충분히 안정적인 서비스다. 다만 내구성이 압도적으로 높다는 차이일 뿐이다. 참고로 99.99%는 S3 Standard의 설계 기준이고, 실제 보장 수준인 SLA는 별도로 정해져 있다.

## S3가 제공하는 기능들

파일 관리에 필요한 기능이 대부분 갖춰져 있다. 이번 챕터에서 차례로 다룬다.

- **Presigned URL**: 제한된 사람에게만 파일 접근이나 업로드 권한을 임시로 부여
- **버저닝**: 파일의 버전 관리
- **권한 관리**: 누가 어떤 파일에 접근할 수 있는지 제어
- **복제**: 파일을 다른 곳으로 주기적으로 복제
- **삭제 방지**: 일정 기간 동안 파일 삭제를 막음
- **암호화**: 저장되는 파일의 암호화

## 용어 정리

| 용어 | 설명 |
|---|---|
| **Amazon S3** | Simple Storage Service. AWS의 오브젝트 스토리지 서비스 |
| **오브젝트 스토리지** | 파일을 데이터·메타데이터·ID 단위의 오브젝트로 관리하는 스토리지. 확장이 매우 쉬움 |
| **파일 스토리지** | 파일을 계층 구조로 관리하는 스토리지. 빠른 탐색·수정이 가능하지만 확장은 제한적 |
| **내구성** | 데이터를 잃어버리지 않을 능력. S3는 99.999999999% |
| **가용성** | 원할 때 데이터에 접근할 수 있는 능력. S3 Standard는 99.99%(설계 기준) |
| **정적 웹 호스팅** | 서버 없이 S3만으로 웹페이지를 제공하는 기능 |
