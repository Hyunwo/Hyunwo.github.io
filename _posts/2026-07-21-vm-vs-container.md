## 공통점: Host Server → Host OS까지는 동일

두 방식 모두 물리 서버 위에 Host OS를 올리는 것까지는 같다. 차이는 그 위에서 "무엇으로 격리하느냐"에 있다.

---

## VM (가상 머신)

![VM 아키텍처]({{ site.baseurl }}/assets/images/vm-vs-container/vm_architecture.png)

- **Hypervisor**(하나의 물리 서버에서 여러 VM을 동시에 실행할 수 있게 해주는 가상화 소프트웨어) 위에 각 VM마다 **독립적인 Guest OS**를 통째로 올린다
- Host OS와 다른 종류의 OS도 설치 가능

---

## Container

![Container 아키텍처]({{ site.baseurl }}/assets/images/vm-vs-container/container_architecture.png)

- Guest OS를 따로 올리지 않고, **컨테이너 런타임**(컨테이너를 만들고 실행/관리하는 소프트웨어, 예: Docker)이 Host OS 자원을 나눠서 여러 컨테이너가 사용
- 격리는 리눅스 커널 기능인
  - **namespace**(프로세스, 네트워크 등 커널 관련 영역을 격리)
  - **cgroups**(CPU, 메모리 등 자원 사용량을 제한)
- **컨테이너 이미지**(서비스 코드와 그 서비스 실행에 필요한 라이브러리를 함께 묶은 패키지)로 컨테이너를 생성
- Host OS와 **다른 커널의 OS는 사용 불가** (예: 리눅스 Host 위에서 윈도우 컨테이너 불가)

---

## 비교표

| 구분       | VM                              | Container                             |
| -------- | ------------------------------- | ------------------------------------- |
| 격리 단위    | Hypervisor + Guest OS 전체        | namespace + cgroups (커널 공유)           |
| OS 독립성   | Host와 다른 OS 설치 가능               | Host OS 커널에 종속                        |
| 보안 격리 수준 | 높음 (Guest OS 단위로 완전 분리)         | 상대적으로 낮음 (커널 공유 → 하나 뚫리면 다른 컨테이너도 위험) |
| 확장 방식    | 특정 모듈에 부하가 와도 OS 전체를 하나 더 띄워야 함 | 모듈(서비스)별로 컨테이너를 쪼개서 필요한 것만 확장 가능      |
| 무게       | 무겁다 (OS 전체 부팅)                  | 가볍다 (커널 공유, 빠른 시작)                    |

**핵심 차이 한 줄 요약**
VM은 OS를 통째로 복제해서 격리하고, Container는 OS 커널은 공유하되 프로세스/자원만 나눠서 격리한다.

---

## Pod 개념

![Pod 개념]({{ site.baseurl }}/assets/images/vm-vs-container/pod_concept.png)

**Pod**는 1개 이상의 컨테이너를 담을 수 있는 쿠버네티스의 최소 배포 단위다.

- 대부분은 **컨테이너 1개 = Pod 1개**로 구성하는 게 일반적인 패턴이지만, 필요하면 여러 컨테이너를 한 Pod에 묶을 수도 있다 (예: 메인 컨테이너 + 로그 수집용 **사이드카** 컨테이너)
- 같은 Pod 안의 컨테이너들은 네트워크(IP, 포트)와 스토리지(볼륨)를 공유한다 → 그래서 서로 아주 밀접하게 붙어서 동작해야 하는 것들만 한 Pod에 묶는 게 원칙

### 왜 Pod 단위로 확장하는가

Container는 서비스를 모듈별로 쪼개서 담을 수 있고, k8s는 이 Pod를 배포/확장의 기본 단위로 삼기 때문에, 부하가 몰리는 특정 모듈(= 특정 Pod)만 골라서 개수를 늘리는 스케일링(**HPA** 등)이 가능하다. 이는 VM에서 "부하 온 모듈 때문에 OS 전체를 통째로 하나 더 띄워야 하는" 비효율과 대비되는 지점이다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| **Hypervisor** | 하나의 물리 서버에서 여러 개의 VM을 동시에 실행할 수 있게 해주는 가상화 소프트웨어 |
| **Guest OS** | VM 안에 개별적으로 설치되는 OS. Host OS와 다른 종류의 OS도 설치 가능 |
| **컨테이너 런타임** | 컨테이너를 만들고 실행/관리하는 소프트웨어 (예: Docker) |
| **컨테이너 이미지** | 서비스 코드와 그 서비스 실행에 필요한 라이브러리를 함께 묶은 패키지 |
| **namespace** | 프로세스, 네트워크 등 커널 관련 영역을 격리하는 리눅스 커널 기능 |
| **cgroups** | CPU, 메모리 등 자원 사용량을 제한하고 격리하는 리눅스 커널 기능 |
| **Pod** | 1개 이상의 컨테이너를 담을 수 있는 쿠버네티스의 최소 배포 단위 |
| **사이드카(Sidecar)** | 메인 컨테이너를 보조하는 역할로 같은 Pod에 함께 배치되는 컨테이너 (예: 로그 수집) |
| **HPA (Horizontal Pod Autoscaler)** | 부하에 따라 Pod 개수를 자동으로 늘리거나 줄여주는 쿠버네티스 오브젝트 |
