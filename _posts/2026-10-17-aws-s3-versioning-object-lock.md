[지난 글](/2026/10/08/aws-s3-storage-classes/)에서 S3의 스토리지 클래스를 정리했다. 이번 글에서는 데이터를 실수로 지우거나 덮어쓰는 사고를 막는 두 가지 기능, **버전 관리(Versioning)** 와 **객체 잠금(Object Lock)** 을 다룬다. 두 기능은 연결되어 있다. 객체 잠금은 버전 관리 위에서 동작하기 때문이다.

## 버전 관리: 객체의 모든 변경 이력을 남긴다

버전 관리를 켜면 객체를 만들고, 수정하고, 삭제하는 모든 단계가 별도의 버전으로 보관된다. 같은 키(`test.jpg`)로 파일을 다시 올려도 기존 파일을 덮어쓰지 않고, 새 **버전 ID**를 가진 새 객체가 쌓인다. 사용자가 읽을 때는 가장 최신 버전이 보인다.

버전 관리는 **버킷 단위**로 설정하고, 기본값은 비활성화(Unversioned)다. 새 버킷을 만들 때 켜거나, 이미 만든 버킷의 속성 탭에서 편집해서 켤 수 있다.

## 삭제 마커: 지워진 것처럼 보일 뿐 데이터는 남아 있다

버전 관리가 켜진 버킷에서 객체를 삭제하면 실제 데이터가 지워지지 않는다. 대신 **삭제 마커(Delete Marker)** 라는 표시가 최신 버전으로 얹힌다. 이후 사용자가 그 키로 요청하면 최신 버전이 삭제 마커이므로 객체가 없는 것처럼 응답을 받는다.

![버전 관리와 삭제 마커의 동작 과정](/assets/images/aws-s3-versioning-object-lock/s3_versioning_delete_marker.png)

위 그림의 흐름을 따라가 보자. ①에서 `test.jpg`를 처음 올리면 버전 ID 11111이 생기고, ②에서 파일을 업데이트하면 22222가 최신이 된다. ③에서 파일을 삭제하면 삭제 마커가 최신 버전이 되어 사용자에게는 삭제된 것처럼 보이지만, 22222와 11111은 그대로 남아 있다. ④처럼 **삭제 마커를 제거하면** 다시 22222가 최신 버전이 되어 파일이 복원된다. 특정 버전을 지워서 11111로 롤백하는 것도 가능하다.

이 구조 때문에 완전히 삭제하려면 **삭제 마커를 포함한 모든 버전을, 버전 ID를 지정해서** 영구 삭제해야 한다. 콘솔에서는 `버전 표시`를 켠 상태에서 각 버전을 선택해 삭제하고 `영구 삭제`를 입력하면 된다.

## 버전 관리 주의점: 보이지 않아도 비용은 나간다

버전 관리에서 가장 조심할 부분은 비용이다. 버전 관리를 켜면 덮어쓸 때마다 파일이 새로 쌓이므로 용량이 빠르게 늘 수 있다. 예를 들어 10GB 객체의 버전이 5개 있으면 사용자가 쓰는 건 최신 10GB뿐이지만 **저장 비용은 50GB 기준**으로 나온다. 삭제 마커가 얹힌 상태도 마찬가지다. 1TB 파일을 지웠다고 생각했는데 마커만 올라갔다면 1TB의 요금이 계속 청구된다. 그래서 버전 관리는 필요한 버킷에만 켜고, 쌓이는 이전 버전을 정리하는 방법을 함께 준비해야 한다. 이 정리는 다음 글에서 다룰 수명 주기 관리와 연동한다.

또 하나 기억할 점은 **한번 켠 버전 관리는 끌 수 없다**는 것이다. 선택지는 `일시 중지(Suspended)`뿐이다. 일시 중지하면 새 버전이 더 쌓이지 않지만, 이미 쌓인 버전은 그대로 남아 비용이 계속 발생한다. 버전 관리 이전 상태로 완전히 돌아가려면 버킷을 삭제하고 다시 만드는 수밖에 없다.

| 상태 | 설명 |
|---|---|
| **비활성화(Unversioned)** | 기본값. 덮어쓰면 이전 데이터는 사라진다 |
| **활성화(Enabled)** | 모든 변경이 버전으로 쌓인다 |
| **일시 중지(Suspended)** | 새 버전 생성을 멈춘다. 기존 버전은 그대로 유지되며, 비활성화로 되돌릴 수는 없다 |

## MFA Delete: 삭제에 추가 인증을 요구하기

**MFA Delete**를 켜면 특정 버전을 영구 삭제하거나 버전 관리 상태를 바꿀 때 MFA 인증을 함께 요구한다. 해커가 계정에 침입해 데이터를 지우거나 내가 실수로 지우는 상황을 한 단계 더 막아 준다. 다만 MFA Delete는 콘솔에서 설정할 수 없고, 버킷 소유 계정의 **루트 사용자가 CLI나 API로** 설정해야 한다. 요청에는 보안 자격 증명과 함께 MFA 장치의 일련번호와 6자리 코드를 이어 붙인 값이 필요하다. 또 **수명 주기 설정과는 함께 쓸 수 없다**는 제약이 있어서, 다음 글에서 다룰 수명 주기로 이전 버전을 정리할 계획이라면 MFA Delete 사용 여부를 먼저 정해야 한다.

## 객체 잠금: 한 번 쓰면 바꿀 수 없게 만들기

**객체 잠금(Object Lock)** 은 WORM(Write Once, Read Many) 모델을 S3에 적용한 기능이다. 정해진 기간 또는 무기한으로 객체의 삭제와 덮어쓰기를 막아서, 법적 규정을 지키거나 중요 데이터를 보호할 때 쓴다. 객체 잠금은 **버전 관리가 켜진 버킷에서만** 동작한다. 한번 객체 잠금을 켠 버킷은 객체 잠금을 끌 수도, 버전 관리를 일시 중지할 수도 없다. 잠금은 객체의 **각 버전 단위**로 적용되어, 같은 객체의 버전마다 모드와 기간이 다를 수 있다.

객체 잠금은 두 종류의 보호 방식으로 나뉜다.

### 보관 모드: 일정 기간 동안 수정·삭제 방지

보관 기간(Retention Period)을 정해 그 기간 동안 보호한다. 기간이 끝나면 다시 삭제와 변경이 가능하다. 버킷에 기본 보관 기간을 일 또는 연 단위로 설정해 두면 새 객체 버전의 생성 시각에 그 기간을 더해 보관 만료일이 정해진다. 모드가 두 가지다.

- **규정 준수 모드(Compliance)**: 가장 강력하다. 보관 기간 동안은 **루트 사용자를 포함한 누구도** 객체 버전을 덮어쓰거나 삭제할 수 없고, 모드를 바꾸거나 보관 기간을 줄이는 것도 불가능하다. 공식 문서에 따르면 보관 기간이 끝나기 전에 삭제할 수 있는 유일한 방법은 AWS 계정 자체를 삭제하는 것이다.
- **거버넌스 모드(Governance)**: 특별한 권한이 없는 사용자만 막는다. `s3:BypassGovernanceRetention` 권한이 있고 요청에 `x-amz-bypass-governance-retention:true` 헤더를 포함하면 삭제하거나 잠금 설정을 바꿀 수 있다(콘솔은 이 헤더를 기본으로 포함한다). "최상위 관리자는 지울 수 있지만 나머지는 못 지우게" 하고 싶을 때 쓴다.

규정 준수 모드는 한번 걸면 되돌릴 수 없으므로, 실제로 적용하기 전에 거버넌스 모드로 동작을 먼저 테스트해 보는 것이 안전하다.

### 법적 보존(Legal Hold): 기간 없이 딱지를 붙여 보호

Legal Hold는 객체 버전에 **딱지(Hold)** 를 붙이는 방식이다. 보관 기간이 없고, 딱지가 붙어 있는 동안에는 삭제와 수정이 불가능하다. 딱지를 떼는 순간 다시 가능해진다. `s3:PutObjectLegalHold` 권한이 있는 사용자는 누구나 자유롭게 붙이고 뗄 수 있으므로, 이 권한을 특정 관리자에게만 주는 식으로 운영한다. 소송이나 감사 때문에 "이 문서는 폐기하면 안 된다"고 표시하는 용도다.

| 구분 | 규정 준수 모드 | 거버넌스 모드 | Legal Hold |
|---|---|---|---|
| 보호 기간 | 보관 기간 동안 | 보관 기간 동안 | 기간 없음, 딱지가 있는 동안 |
| 루트 사용자 | 변경·삭제 불가 | 우회 권한이 있으면 가능 | 홀드 권한이 있으면 해제 가능 |
| 해제 방법 | 기간 만료만 가능 | 우회 권한 사용 또는 기간 만료 | 홀드 제거 |
| 주 용도 | 법적 보관 의무 | 일반적 보호, 사전 테스트 | 소송·감사 대응 |

객체 잠금이 걸린 버킷에서 버전 ID를 지정해 영구 삭제하면 `403 Forbidden`으로 거부된다. 버전 ID 없이 일반 삭제를 하면 `200 OK`와 함께 삭제 마커가 추가되지만, 잠긴 **버전 자체는 지워지지 않고** 그대로 보호된다. 보관 기간이나 Legal Hold는 새 버전 생성이나 삭제 마커 추가를 막지 않는다. 또 객체 잠금이 걸린 이전 버전은 수명 주기 만료 규칙의 대상에서도 제외된다.

## 실습: 버전 관리 켜고 삭제 마커 확인하기

1. S3에서 `버킷 만들기`를 누르고 이름을 `demo-my-versioning-test`처럼 정한다. 이름은 전역에서 고유해야 하므로 계정 ID 등을 붙여 겹치지 않게 한다.
2. 아래로 내려가 **버킷 버전 관리**를 `활성화`로 선택하고 버킷을 만든다. 만들 때 놓쳤다면 버킷의 `속성` 탭에서 편집해서 켤 수 있다. 여기서 보면 비활성화 옵션은 없고 일시 중지만 있다.
3. 파일을 올리고 다시 올려 버전이 쌓이는 것을 확인한다. 객체 목록에서 `버전 표시`를 켜면 버전 ID별로 보인다.
4. 객체를 삭제해 본다. `버전 표시`를 끈 목록에서는 사라진 것처럼 보이지만, 켜 보면 삭제 마커가 얹힌 채 이전 버전이 그대로 남아 있다.
5. 완전히 지우려면 `버전 표시` 상태에서 모든 버전과 삭제 마커를 선택해 `영구 삭제`를 입력한다. 그러면 객체가 완전히 사라진다.

버전이 계속 쌓이는 문제를 어떻게 관리하는지는 다음 글에서 이어서 다룬다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| **버전 관리(Versioning)** | 객체의 모든 변경 이력을 버전으로 보관하는 버킷 단위 기능. 켜면 끌 수 없고 일시 중지만 가능 |
| **버전 ID** | 같은 키의 각 버전을 구분하는 식별자 |
| **삭제 마커(Delete Marker)** | 버전 관리 버킷에서 삭제 시 얹히는 표시. 이전 버전은 그대로 남는다 |
| **일시 중지(Suspended)** | 새 버전 생성을 멈추는 상태. 기존 버전은 유지된다 |
| **MFA Delete** | 버전 영구 삭제·버전 관리 상태 변경에 MFA를 요구하는 설정. 루트 사용자가 CLI/API로 설정하며 수명 주기와 함께 쓸 수 없다 |
| **객체 잠금(Object Lock)** | WORM 모델로 객체 버전의 삭제·덮어쓰기를 막는 기능. 버전 관리 버킷에서만 동작하고 한번 켜면 끌 수 없다 |
| **규정 준수 모드** | 보관 기간 동안 루트를 포함한 누구도 삭제·변경 불가 |
| **거버넌스 모드** | 우회 권한이 없는 사용자만 막는 보관 모드 |
| **Legal Hold** | 기간 없이 딱지를 붙여 삭제·수정을 막는 방식 |

다음 글에서는 버전이 쌓이는 문제를 해결하는 수명 주기 관리(Lifecycle)를 다룬다.
