AWS VPC를 제대로 이해하려면 그 밑에 깔린 네트워크 기초(사설망, NAT, CIDR, 서브넷)부터 정리하고 가야 한다. 순서대로 정리한다.

## 사설망(Private Network): 왜 필요한가

IPv4는 32비트라 최대 **약 43억 개(4,294,967,296개)**의 주소밖에 못 만든다. 전 세계 기기 수를 생각하면 턱없이 부족하다. 그래서 등장한 개념이 **사설망**이다.

- 사설망 내부는 외부 인터넷과 직접 통신이 불가능한 **사설 IP**로 구성한다
- 외부와 통신할 때는 통신 가능한 **공인 IP**로 바꿔서 나간다
- 보통 하나의 망은 사설 IP를 쓰는 기기들 + NAT 기능을 갖춘 **Gateway**로 구성된다

같은 사설 IP 대역(예: `192.168.0.x`)을 여러 회사, 여러 가정에서 동시에 써도 문제없다. 서로 다른 사설망 안에서만 쓰이고 외부로 그대로 나가지 않기 때문이다. 이렇게 제한된 공인 IP를 아껴 쓰기 위해 만든 개념이 사설망이다.

**참고로 IPv6는 사정이 다르다.** IPv6는 128비트라 최대 주소 개수가 **2^128개**(약 3.4×10^38개)로, IPv4보다 **2^96배** 많다. 사실상 무한에 가까운 주소라, IPv6 환경에서는 주소 부족 문제 자체가 없어서 사설망이라는 개념이 원래의 목적으로는 필요 없다.

## NAT(Network Address Translation): 사설 IP가 외부와 통신하는 방법

사설 IP는 그 자체로는 외부와 통신할 수 없어서, 공인 IP로 변환해주는 과정이 필요하다. 이 변환 방식이 3가지다.

![NAT의 3가지 종류]({{ site.baseurl }}/assets/images/aws-networking-basics/nat_types_comparison.png)

- **Dynamic NAT**: 사설 IP 1개를 공인 IP 1개로 연결하는데, 그 공인 IP는 **NAT Pool**(사용 가능한 공인 IP 그룹)에서 그때그때 비어있는 걸 가져다 쓴다. 그래서 같은 사설 IP라도 접속할 때마다 다른 공인 IP로 나갈 수 있다
- **Static NAT**: 사설 IP 1개를 **항상 같은** 공인 IP 1개로 고정 연결한다. **AWS의 Internet Gateway가 이 방식을 쓴다** — EC2 인스턴스의 Private IP와 Public/Elastic IP가 1:1로 고정 매핑된다
- **PAT (Port Address Translation)**: 여러 개의 사설 IP를 공인 IP **1개**로 연결하는 방식. IP만으로는 구분이 안 되니까 **포트 번호**로 각 연결을 구분한다. 예를 들어 `192.168.0.2:5000`과 `192.168.0.5:5000`이 같은 공인 IP `181.227.3.33`을 쓰더라도, 각각 `:50001`, `:50002`처럼 다른 포트로 나가기 때문에 돌아오는 응답도 정확히 원래 기기로 찾아간다

### 헷갈리기 쉬운 포인트: Internet Gateway ≠ NAT Gateway

AWS에는 이름이 비슷한 두 컴포넌트가 있는데 동작 방식이 다르다.

- **Internet Gateway (IGW)**: 퍼블릭 서브넷의 인스턴스가 인터넷과 양방향으로 통신할 때 쓴다. **Static NAT**(1:1 고정 매핑) 방식이라, 외부에서 먼저 접속을 시작할 수도 있다
- **NAT Gateway**: 프라이빗 서브넷의 인스턴스가 인터넷으로 **나가기만** 할 때 쓴다. **PAT**(다대일) 방식이라, 여러 프라이빗 IP가 NAT Gateway의 공인 IP 하나를 공유해서 나간다. 외부에서 먼저 접속을 시작하는 건 막혀있다

이름이 비슷해서 같은 걸로 착각하기 쉬운데, **하나는 Static NAT, 하나는 PAT**로 전혀 다른 방식이라는 걸 기억해두면 헷갈리지 않는다.

## CIDR (Classless Inter-Domain Routing): IP 범위를 나타내는 표기법

CIDR은 IP 주소의 영역을 네트워크 단위로 나누기 위해 IP를 묶는 방식이다. 여러 개의 사설망을 구축하려면 이렇게 망을 나누는 방법이 필요하다.

### 표기법: A.B.C.D/E

- `A.B.C.D`: 네트워크 주소 + 호스트 주소를 합친 IP
- `E` (0~32): 앞에서부터 **네트워크 주소가 몇 비트인지**를 나타낸다

![CIDR Notation 읽는 법]({{ site.baseurl }}/assets/images/aws-networking-basics/cidr_notation.png)

`192.168.2.0/24`를 예로 들면:

- `/24` → 네트워크 비트가 24개라는 뜻. IP 전체가 32비트이므로, 호스트 비트는 `32 - 24 = 8개`
- 호스트 비트 8개로 표현 가능한 주소 개수는 `2^8 = 256개`
- 즉 이 CIDR 블록은 `192.168.2.0`부터 `192.168.2.255`까지 총 256개의 주소를 의미한다

숫자가 작을수록(`/16`) 네트워크 비트가 적어서 범위가 넓어지고, 숫자가 클수록(`/28`) 범위가 좁아진다.

**응용 예시**: `10.88.135.144/28`이면 호스트 비트는 `32-28=4개`, 즉 `2^4=16개`의 주소 범위를 갖는다. 이렇게 CIDR 표기법 하나만 알면 그 네트워크가 몇 개의 IP를 담을 수 있는지 바로 계산할 수 있다.

## 서브넷: 네트워크 안의 네트워크

서브넷은 큰 네트워크를 더 작은 단위로 잘게 쪼갠 것이다. 큰 네트워크에 부여된 IP 범위를 일정하게 잘라서, 각 서브넷에 나눠 할당하는 방식으로 만든다.

![서브넷: 큰 네트워크를 잘게 쪼갠 단위]({{ site.baseurl }}/assets/images/aws-networking-basics/subnet_concept.png)

예를 들어 `192.168.0.0/16`(65,536개 주소를 가진 큰 네트워크)을 `/24` 단위로 쪼개면, 각각 256개 주소를 가진 서브넷을 여러 개 만들 수 있다. 이렇게 나눈 서브넷마다 별도의 Gateway를 두고, 용도에 따라(웹서버용, DB용, 관리용 등) 독립적으로 관리할 수 있다.

이게 바로 AWS VPC 안에서 퍼블릭 서브넷/프라이빗 서브넷을 나누는 방식의 기초 원리다. VPC 자체가 큰 CIDR 블록을 가진 네트워크이고, 그 안의 서브넷들이 이 CIDR을 잘게 쪼갠 단위인 셈이다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| **사설망 (Private Network)** | 외부 인터넷과 직접 통신 불가능한 사설 IP로 구성된 내부 네트워크 |
| **사설 IP / 공인 IP** | 내부에서만 쓰는 IP / 인터넷에서 실제로 통신 가능한 IP |
| **NAT** | 사설 IP를 공인 IP로 변환해 통신 가능하게 해주는 기술 |
| **Dynamic NAT** | 사설 IP 1개를 NAT Pool에서 가져온 공인 IP 1개로 그때그때 연결 |
| **Static NAT** | 사설 IP 1개를 항상 같은 공인 IP 1개로 고정 연결. AWS Internet Gateway가 이 방식 |
| **PAT** | 여러 사설 IP를 공인 IP 1개로 연결하되 포트 번호로 구분. AWS NAT Gateway가 이 방식 |
| **CIDR** | IP 주소 범위를 A.B.C.D/E 형식으로 표기하는 방법 |
| **네트워크 비트 / 호스트 비트** | CIDR에서 고정된 앞부분(네트워크) 비트 수 / 실제 배정 가능한 뒷부분(호스트) 비트 수 |
| **서브넷** | 큰 네트워크를 더 작은 CIDR 범위로 쪼갠 단위 |
